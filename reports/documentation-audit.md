# Documentation fact-check and evidence ledger

Audit revision: 2026-09-08. Baseline documentation: Git commit [`d0cd2c07e3641531c39037223eb98e309f44c4dc`](https://github.com/BurnyCoder/rl-locomotion-steering-vectors/tree/d0cd2c07e3641531c39037223eb98e309f44c4dc). This is a documentation and saved-data audit, not another locomotion experiment. The measured outcomes, vectors, thresholds, selections, episode files, and original generated experiment reports are preserved. Corrected narrative reports and the paper supersede their earlier prose; Git and Hugging Face revisions retain publication history.

## Findings and limits

The read-only investigation reproduced all 332 saved validation/confirmation condition comparisons, including paired effects, percentile-bootstrap intervals, episode means, and failure fractions. It also reproduced primary fitting directions and activation RMS, checked disjoint seed partitions, and verified the imported 003/004 vector families. The reproducible audit below records the precise checks and tolerances. These checks support the numbers under the implemented estimators; they do not establish that the estimators answer every possible safety or behavioral question.

No headline numerical correction was required. The Ant effect is a change in **world-coordinate Y velocity**, with evidence of heading involvement. Its original status remains `confirmation_failed`; no replication or practical-target application data exist. Gait preservation, pure body-relative strafing, semantic disentanglement, generalization across independently trained policies, and a completed discovery are not established. See the [measured Ant results](ant-classic-005/results.json), [causal audit](ant-classic-005-causal-audit.md), and [original prefix-failure audit](ant-classic-005/prefix-failure-audit.json).

“Verified” below means checked against the specified evidence within this audit's scope. It is not a guarantee that no software defect, missing observation, or unsupported interpretation remains. Upstream documentation is evidence of what its authors report; it is not an independent reproduction of upstream training. Project thresholds and procedural choices are identified as such rather than attributed to the libraries used to implement them.

## Reproduction and evidence files

After the README installation, restore the published episode arrays. In a fresh clone without existing `runs/` data, the following PowerShell commands download only episode evidence from the pinned publication and combine it with the committed compact results:

```powershell
uv run hf download BurnyCoder/rl-locomotion-steering-vectors --revision f3749ef3216671bb5e25baad5e389c94f319c422 --include "experiments/*/episodes/*" --local-dir artifacts/documentation-audit-download
foreach ($run in @('hc-classic-001', 'hc-running-002', 'hc-height-speed-003', 'hc-height-speed-004', 'ant-classic-005')) {
    New-Item -ItemType Directory -Path "runs/$run" -Force | Out-Null
    Copy-Item -LiteralPath "reports/$run/results.json" -Destination "runs/$run/results.json"
    Copy-Item -LiteralPath "artifacts/documentation-audit-download/experiments/$run/episodes" -Destination "runs/$run" -Recurse
}
```

The [Hugging Face download CLI](https://huggingface.co/docs/huggingface_hub/guides/cli#hf-download) preserves the repository-relative directory structure. Existing original run directories can be used directly; do not copy another experiment over them. The offline audit itself reads saved arrays only; it does not download or load policy weights, invoke a simulator, or allocate new experimental seeds:

```powershell
uv run --no-sync python scripts/audit_documentation.py
```

The [thin audit command](../scripts/audit_documentation.py) calls [phase checks](../scripts/documentation_checks.py) and [independent NumPy reductions](../scripts/documentation_evidence.py), rather than the production effect/extraction functions. Its outputs are [numerical verification](documentation-audit/numerical-audit.json), [Ant sensitivity verification](documentation-audit/ant-sensitivity-verification.json), [input hashes](documentation-audit/input-identities.json), and timestamped logs in `reports/documentation-audit/`. The completed run checked 332 conditions and 63,549 leaf fields, with zero mismatches or failed phases; the largest numerical difference was `2.220446049250313e-16` against a `1e-12` absolute tolerance. All 3,892 consumed input files retained their hashes. Field counts include metadata and provenance comparisons, not independent experiments.

The [original Ant fitting-inspection JSON](ant-classic-005/audit/fitting-inspection.json) is published unchanged, SHA256 `b2d8db9239a36c84f9c3f6a4889715f627a14119b5fe7db018e9b31a500e1898`; the [calculation notes](ant-classic-005/audit/reproduction.md) explain its reproduction. The command reproduces all of that JSON's numerical fields, excluding its historical scope/chronology prose. It also reproduces the decisive 001 direction-sensitivity table, floor exclusions and first-window check; it does not repeat every historical 001 diagnostic narrative calculation. Those claims retain their original saved-data and inspection references.

The earlier targeted Ant checks remain available: [mathematical audit command](../scripts/audit_ant005_math.py), [mathematical results](ant-classic-005/math-audit.json), [runtime audit command](../scripts/audit_ant005_runtime.py), and [runtime results](ant-classic-005/runtime-audit.json). Runtime replay was part of that earlier audit; no new simulation was needed for this documentation revision. `results.json` is the compact source of each condition's `vector`, `alpha`, `behavior`, and `effect`; raw trajectories live under the corresponding run's `episodes/<phase>/<condition>/` directory. The ledger uses these keys instead of unstable prose line numbers.

## Test history and current-state claims

The pre-correction core suite was run with `uv run --no-sync pytest --ignore=tests/test_pgs.py -q` at the baseline commit. The [first complete log](documentation-audit/tests-initial.log) records **80 passed, one failed**: `test_calibration_uses_only_the_configured_grid` encountered `PermissionError: [WinError 5]` during JSON `Path.replace`. The [targeted retry](documentation-audit/tests-targeted-retry.log) passed, and the [full retry](documentation-audit/tests-full-retry.log) passed **81 tests in 19.18 seconds**. Both retries used unchanged production code. The original failure is retained; its specific operating-system cause was not determined. Python documents [Path.replace](https://docs.python.org/3.12/library/pathlib.html#pathlib.Path.replace) and the underlying [os.replace](https://docs.python.org/3.12/library/os.html#os.replace), but those references do not diagnose this machine's transient error.

The paused, untracked PGS implementation/tests are outside the evaluated core and remain unpublished. The [first integrated audit-test run](documentation-audit/tests-current.log) exposed a new test import issue: the documented `pytest` executable did not put the repository root on `sys.path`, unlike the earlier targeted `python -m pytest` runs. The [pytest configuration](../pyproject.toml) now explicitly includes the root through the [documented pythonpath setting](https://docs.pytest.org/en/stable/explanation/pythonpath.html). The [final documented-command run](documentation-audit/tests-final.log) passed **95 tests in 20.09 seconds**, comprising the original 81 plus six numerical-audit and eight publication-audit tests. No scientific runtime logic changed. A passing suite supports its tested software contracts, not scientific usefulness or absence of every defect.

The public-copy check is separately reproducible:

```powershell
uv run --no-sync python scripts/verify_documentation_publication.py --revision main --github-revision main
```

The [publication verifier](../scripts/verify_documentation_publication.py) resolves each service's commit separately, compares the 52 original compact bundle artifacts, requests the three movie headers, and counts actual README video elements without saving signed redirects or HTML. This is not a frame-identity test; the saved replay audits provide that evidence. The [pre-update check](documentation-audit/publication-before.json) found three supporting audits absent from Hugging Face: 003/004 `vector-import-audit.json` and 002 `quality-analysis-audit.json`. They were already public in Git. All 49 available compact files matched, and the three movies/players were accessible. These three gaps are included in this publication update alongside the original Ant sensitivity JSON. The first verifier draft also mistakenly mapped paper figures into experiment directories; the explicit five-bundle filter and its test fixed that audit-tool defect. Original scientific artifacts were unaffected.

## Interpretation and publication policy

The substantive review covered calculation independence, pairing and aggregation, deserialization, file scope, error retention, publication identities, maintainability, and tests. It found the verifier's overly broad file mapping and missing failure-record handling; the revised verifier restricts its inventory, records each failed check safely, and rejects partial or empty results after saving evidence. Focused tests cover episode weighting, within-window RMS, paired identities, early endings, sensitivity exclusions, preservation comparisons, unavailable publications, and separate service revisions. These checks complement the full suite; they do not constitute outside peer review.

This revision corrects descriptions of the existing research. It does not relax acceptance criteria, remove failed pairs, reinterpret validation controls as confirmed discoveries, or consume new confirmation seeds. Original outcome files remain available in Git/Hugging Face history and unchanged in the local runs. The next scientific step is outside this audit; any new hypothesis requires its own protocol and fresh evaluation evidence.

Evidence that was never recorded cannot be recovered by confident prose. The unresolved limits above remain explicit after publication. Sources are attached to claims where they can support them; interpretations are labeled as interpretations instead of being made to look established by an unrelated citation.
