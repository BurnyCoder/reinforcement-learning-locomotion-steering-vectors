# Experimental methodology

## Question and hypothesis

Can a constant offset at an internal layer of a frozen locomotion policy reliably change a useful behavior while preserving movement? The initial hypothesis is that contrasting naturally occurring behavior produces a direction with a stronger useful effect than generic perturbations. This is an adaptation of contrastive activation addition to continuous control, not a claim established by its original language-model paper. Sources are catalogued in [sources.md](sources.md).

There is no overall local-compute budget. Individual experiments remain finite, specified, checkpointed, and reviewed. A failed contrast or failed confirmation motivates a new hypothesis; it does not justify repeatedly selecting favorable test episodes. The first implementation does not train a new policy.

## Policy and intervention

The starting checkpoints are Farama-Minari's [HalfCheetah-v5 TQC medium](https://huggingface.co/farama-minari/HalfCheetah-v5-TQC-medium/tree/b4ce04da6f246f06ae4c4258b8ab39624e6600b4) and [Ant-v5 SAC medium](https://huggingface.co/farama-minari/Ant-v5-SAC-medium/tree/de5978d34b0118341df2b0a30232c5d2bfcb148e) policies. This project evaluates one checkpoint per policy; both checkpoint metadata records specify seed 0. Upstream documentation and training code identify RL provenance, but the complete upstream training history has not been independently reproduced. Policy parameters remain frozen during collection, extraction, calibration, and evaluation. Pretrained model revision, file hash, software versions, and observation/action spaces must be retained with each run; [sources.md](sources.md#scientific-method-and-rl-policies) separates upstream attribution from local verification.

The intervention site is the output of `actor.latent_pi[1]`, the first ReLU in the expected two-hidden-layer actor. Runtime architecture checks guard this assumption. The next nonlinear layer gives the direction an opportunity to change state-dependent action computation. The activation rule is `h_new = h + alpha * d_scaled`, where `alpha` is constant over the intervention segment. [Pinned Baukit Trace](https://github.com/davidbau/baukit/blob/9d51abd51ebf29769aecc38c4cbef459b731a36e/baukit/nethook.py#L65-L101) owns hook registration and removal; the remaining [SB3 SAC actor](https://github.com/DLR-RM/stable-baselines3/blob/v2.4.1/stable_baselines3/sac/policies.py#L147-L176) still computes the action.

## Data collection and vector extraction

With seed offset zero, reset partitions are diagnostic `0-15`, fitting `1000-1063`, validation `10000-10009`, confirmation `20000-20029`, and replication `30000-30029`. The configured `STEERING_SEED_OFFSET` is added to every seed; `hc-running-002` uses `100000` so all partitions are fresh relative to experiment 001. The manifest records actual configuration and full seed lists. All data derived from an episode stay in its partition.

The default horizon is 1,000 steps and steering starts after a 100-step unsteered prefix; each manifest records the actual configuration. Diagnostic and fitting episodes use stochastic unsteered policy actions. Fitting uses non-overlapping 100-step windows after startup. This allows local behavioral variation even when whole-episode speed is nearly constant. Incomplete or unhealthy fitting windows are excluded with recorded reasons; failed evaluation episodes remain in the analysis.

Experiment 001 used health-only eligibility. Its [fitting review](../reports/hc-classic-001-diagnostics.md) found substantial influence from ten near-stationary windows. The follow-up adds `STEERING_FIT_MIN_SPEED_FRACTION=0.5`: calculate the median forward speed among finite, initially health-eligible fitting windows and retain only windows strictly above half that median. The fraction, derived absolute floor, and excluded count are saved. A fraction of zero disables this rule. The rule affects both contrast extraction and activation RMS, never evaluation episodes. It is a project pilot heuristic motivated by fitting-only sensitivity analysis; it does not guarantee that posture or effort contrasts are free of speed confounding.

For each behavior, upper and lower quartiles define contrasting activation means. Each group needs at least eight independent contributing episodes. Contributing episodes receive equal weight within each group, so many windows from a single episode do not manufacture independent evidence. The raw direction is `mean(h_high) - mean(h_low)`. Effort contrasts are formed within up to five speed bins, with equal bin weighting, to reduce speed confounding; coarse bins do not eliminate it.

Vector magnitude is normalized to the fitting set's centered activation RMS, including variation within eligible windows and equal episode weighting. Quartile gaps must exceed `1e-8 * max(1, mean absolute label)`, and raw vector norms must exceed `max(1e-12, RMS * 1e-8)`. These small numerical tolerances prevent normalizing accidental floating-point differences; they are not usefulness thresholds. Nonfinite vectors and insufficient independent contrast are rejected. The diagnostics record the raw direction, scale, contributing episodes, and exclusion reasons. A lack of natural contrast is a diagnosed failure mode rather than a null intervention experiment.

## Calibration, controls, and fresh evaluation

The initial nonzero strength grid is `+/-0.05, +/-0.1, +/-0.2, +/-0.5`; `STEERING_STRENGTH_GRID` can register a different signed grid for a new experiment. Zero steering is a shared paired baseline collected once per evaluation split. Evaluation uses deterministic actions and paired reset seeds. Pairs that reach intervention must have matching hashes of complete simulator integration states immediately before the first steered action. This supports a causal comparison within the tested simulator and policy. Episodes that end earlier remain recorded and are subject to the strict prefix-only veto below.

Each fitted candidate receives three norm-matched random directions. A norm-matched shuffled-label direction is added when its contrast is supported and non-negligible; otherwise the implementation records `shuffled_control_skipped` without replacing it ([extraction code](https://github.com/BurnyCoder/rl-locomotion-steering-vectors/blob/d0cd2c07e3641531c39037223eb98e309f44c4dc/src/rl_locomotion_steering_vectors/analysis.py#L172-L190)). Every actual family in experiments 001–005 includes all four controls. Available controls receive the same signed validation grid. A candidate must pass the usefulness gate to be shortlisted. Per vector, the selection favors the smallest absolute strength within 5% of the largest absolute useful effect; controls without a useful grid point retain a strong measured comparison instead of disappearing. Selected signs and strengths are recorded before confirmation. Later report rendering cannot choose a different strength.

For shortlisted candidate vectors, the pipeline fits a constant action-bias comparator from every tenth post-startup fitting observation. It averages the steered-minus-baseline deterministic action displacement at the validation-selected activation strength. The stored bias is divided by `max(abs(value) for value in config.strengths)`, so multiplying it by that positive maximum reproduces the fitted mean displacement before action clipping: `0.5` for the original grid and `0.04` for experiment 004's fine grid ([normalization call](https://github.com/BurnyCoder/rl-locomotion-steering-vectors/blob/d0cd2c07e3641531c39037223eb98e309f44c4dc/src/rl_locomotion_steering_vectors/phases.py#L35-L39), [bias calculation](https://github.com/BurnyCoder/rl-locomotion-steering-vectors/blob/d0cd2c07e3641531c39037223eb98e309f44c4dc/src/rl_locomotion_steering_vectors/experiment.py#L72-L86)). The registered grid supplies the actual tested offsets and signs; an asymmetric grid need not include the positive maximum. Action biases have action dimensions, are stored separately, and are applied after warmup with action-bound clipping. They test whether useful effects also arise from a simple fixed motor-command offset.

Fresh confirmation and replication episodes evaluate locked candidates. Confidence intervals are percentile bootstraps of paired episode differences, not independent resampling of correlated timesteps. Replication here means new reset episodes using the same policy checkpoint. One trained policy cannot establish robustness to the training seed.

Velocity and posture outcomes are first averaged over each episode's recorded post-onset transitions, then averaged equally across episodes. A short failed episode therefore has the same episode weight as a complete one. Forward-speed retention is the ratio of these treated and baseline mean X velocities; it is not a ratio of total distance traveled. The separately saved distance is integrated X displacement over the available post-onset transitions. Different episode lengths prevent treating mean-speed retention as distance retention. The same equal-episode reduction defines planar-speed and quality summaries ([recorded estimator](https://github.com/BurnyCoder/rl-locomotion-steering-vectors/blob/d0cd2c07e3641531c39037223eb98e309f44c4dc/src/rl_locomotion_steering_vectors/analysis.py#L194-L261)).

An explicitly registered cross-behavior experiment can test an existing vector against a different outcome. `retarget` copies the complete candidate/control family without changing its values, keeps the source diagnostic/fitting partitions, and requires fresh evaluation partitions disjoint from the source evaluation. `retarget.json` records the source manifest, extraction name, new target, and every imported array's shape, dtype, and hash. Vector keys in the new run use the new target name, while diagnostics retain the original extraction label. Hypothesis formation may use earlier validation; later fresh evidence must not be described as if the new target had been specified in the parent experiment.

| Behavior | Initial practical effect threshold | Movement preservation |
| --- | --- | --- |
| Speed | At least 5% sustained absolute change | Retain at least 50% of baseline forward speed |
| Effort | At least 10% lower mean squared action | Speed within 5% of baseline |
| Height | At least 0.03 m sustained torso-height change | Speed within 10% of baseline |
| Lateral movement | At least 0.2 m/s directed change | Retain 80% of baseline mean forward speed |
| Turning | At least 0.1 rad/s directed yaw-rate change | Retain 80% of baseline planar speed |

A useful condition must also have a confidence interval excluding zero and avoid increasing the observed failure rate or mean inversion/forbidden-ground-contact fractions by more than five percentage points. Failure is classified for each episode before computing its frequency: an episode fails when its post-onset inversion or forbidden head/torso-ground-contact fraction is strictly greater than 5%, or it has an explicit recorded failure, environment termination, or no post-onset transitions. Existing explicit failure values are retained rather than replaced. Inversion/contact summaries average each episode's fraction equally; they do not pool every timestep across unequal-length episodes. The five-percentage-point checks concern differences of these observed fractions, not confidence bounds on population safety.

The implemented strict gate has an additional veto: **neither arm may contain any prefix-only episode**, defined as `length <= warmup`. Such episodes remain in all paired denominators, count as failures, and receive zero for unavailable post-onset behavioral outcomes. A shared early termination therefore fails the gate even when it contributes zero to the treatment-minus-baseline failure-rate difference ([exact gate](https://github.com/BurnyCoder/rl-locomotion-steering-vectors/blob/d0cd2c07e3641531c39037223eb98e309f44c4dc/src/rl_locomotion_steering_vectors/analysis.py#L203-L247)). This is the original rule retained for Ant005. These are project pilot heuristics, separate from [Gymnasium Ant's termination rule](https://github.com/Farama-Foundation/Gymnasium/blob/v1.0.0/gymnasium/envs/mujoco/ant_v5.py#L337-L371); they do not prove an internal semantic concept.

This episode-level physical-failure measurement was registered during `hc-running-002` validation review, before selection or any confirmation data. The [inspection report](../reports/hc-running-002-validation-inspection.md) found that a 4.47% mean contact fraction hid one episode stalled on its head for 400 consecutive steps. Across ten paired episodes, one additional physical failure is a ten-percentage-point failure increase and therefore exceeds the existing five-percentage-point allowance. Averaging contact duration across trials alone would miss that distinction.

The review paused calibration after 74 conditions. Those original derived estimates remain in `runs/hc-running-002/validation_pooled-quality-v1.json`; cached raw rollouts, vectors, and simulator measurements were not changed. All 120 validation conditions were subsequently analyzed using the revised derived failure criterion, with no primary candidate selected. This is an explicitly documented measurement revision informed by exploratory validation, not a claim that the original calibration protocol was untouched. No held-out evidence informed the revision, and all failed episodes remain in statistical denominators. The completed [experiment findings](../reports/hc-running-002-findings.md) and its comparison audit retain the outcome and both analysis versions.

Mean squared normalized action is an effort proxy. It is not motor energy, battery consumption, or mechanical work. Changes in effort must be interpreted alongside movement, original reward, action saturation, and locomotion-quality metrics. Turning uses yaw-rate geometry rather than reading a quaternion component as an angle.

## Fixed-speed application

The implemented `demonstrate` command supports recorded replicated speed or lateral candidates. If several exist, it chooses the smallest absolute strength, breaking ties by vector name, before collecting application data. Its target is that exact condition's validation mean velocity. Speed uses a tolerance of 5% of the validation baseline speed; signed world-Y lateral velocity uses a fixed 0.2 m/s tolerance. This is a fixed calibrated intervention, without application-time feedback or strength retuning.

Ten new paired reset seeds start at the saved seed offset plus 40000; checks reject overlap with current or inherited source partitions. At least 80% of steered episodes must have post-onset mean velocity inside the target band, treatment must have zero physical failures, and the fresh paired effect must pass the existing behavior-specific usefulness gate in the locked direction. Speed additionally requires zero baseline failures. Lateral retains and reports baseline failures under the paired quality gate, including its strict pre-onset rule. These application thresholds are project pilot choices. The specification and vector/policy hashes are written before collection; failed applications remain recorded.

Media use the first three predetermined application seeds for paired baseline/steered videos, with bitwise replay checks against numerical episodes. The first seed also supplies an off/on/off trial with removal at step 600 and velocity/height plots; lateral adds forward-velocity and ground-plane trajectory plots. The saved horizon must satisfy `warmup < 600 < max_steps`. Removing the hook restores the original policy function at identical observations; it does not restore an earlier physical state or undo trajectory history. No experiment through 005 has qualified for this application stage. The published Ant videos illustrate existing validation episodes and do not claim an application result.

## Interpretation and escalation

Report a direction as useful only when its locked effect and quality conditions survive fresh evaluation. Check random and shuffled controls before claiming specificity. Report one-sided effects, disruptive effects, insufficient contrast, and null results explicitly.

A passing replication gate does not establish an application; the fixed-target workflow above supplies a separate test. The general replay command also supports saved activation directions, chosen reset seeds, MP4/NPZ output, and off/on/off interventions through a later switch-off step. Possible escalation includes a continuous-action adaptation of policy-gradient steering or an online-RL policy trained to respond to varied commands. These additions require their own implementation, validation, source review, and experiment specification. No behavioral cloning is permitted.

The research loop is: define a question, inspect prior work and diagnostics, state a hypothesis, run an experiment, interpret all results, and revise the hypothesis. Keep the reasoning for each change in its experiment report, including what failed, why the next intervention is plausible, and which fresh data will test it.

The [documentation audit](../reports/documentation-audit.md) records corrections to these descriptions and their evidence. Clarifying the estimator or a historical rule does not reanalyze an experiment or change its recorded acceptance status.
