# Sources and reuse audit

Audited September 2026. Links below distinguish what the source establishes from this project's adaptation. Runtime compatibility claims require actual local checks; a generic API signature alone is insufficient. The [documentation audit](../reports/documentation-audit.md) records the checked claims, corrections, and verification limits.

The inspected checkpoint metadata records seed 0 for both policies. The pinned upstream [training loop](https://github.com/Farama-Foundation/minari-dataset-generation-scripts/blob/e74f9d0524c6df014c5a9985d0804001b9ce40dc/scripts/mujoco/train.py#L135-L173) uses SB3 learning in simulator environments and supports multiple runs; the [upload script](https://github.com/Farama-Foundation/minari-dataset-generation-scripts/blob/e74f9d0524c6df014c5a9985d0804001b9ce40dc/scripts/mujoco/upload_model.py#L23-L47) selects a seed-0 checkpoint. These sources support attribution to upstream RL, not an independently reconstructed history of every upstream run or checkpoint-selection decision. This project evaluates one checkpoint per policy and verifies its bytes and inference behavior.

The [official HalfCheetah episode-end documentation](https://gymnasium.farama.org/environments/mujoco/half_cheetah/#episode-end) and [pinned environment implementation](https://github.com/Farama-Foundation/Gymnasium/blob/v1.0.0/gymnasium/envs/mujoco/half_cheetah_v5.py) establish that ordinary HalfCheetah episodes do not terminate merely because locomotion fails physically. They do not prescribe this project's quality thresholds. The [002 validation inspection](../reports/hc-running-002-validation-inspection.md) motivated classifying physical failure per episode before averaging failure frequency: post-onset inversion or forbidden-contact fraction above 5%, combined with existing explicit failures. The 5% episode cutoffs and maximum five-percentage-point failure increase are project pilot choices. This measurement revision was registered before selection/confirmation; old derived validation estimates and original trajectories are retained for audit.

## Why Baukit is the initial intervention dependency

[Baukit's pinned Trace implementation](https://github.com/davidbau/baukit/blob/9d51abd51ebf29769aecc38c4cbef459b731a36e/baukit/nethook.py) accepts an arbitrary PyTorch module, captures output, allows a differentiable `edit_output` callable, and removes its forward hook on context exit. That interface fits repeated ordinary SB3 predictions without tokenization or a different model-execution API. This project reuses that implementation and owns only the locomotion-specific wrapper and experiment logic.

[Package metadata](https://github.com/davidbau/baukit/blob/9d51abd51ebf29769aecc38c4cbef459b731a36e/setup.cfg) advertises Python >=3.7, OS independence, and an MIT classifier. The repository does not supply a full root LICENSE file at that revision, and GitHub's license detector returned no recognized license during this audit. This is documented provenance, not a claim that license text was verified. The [pinned commit](https://github.com/davidbau/baukit/commit/9d51abd51ebf29769aecc38c4cbef459b731a36e) is dated 22 February 2024. Package import also loads Torchvision, so Torch and Torchvision are pinned together.

Alternative libraries were inspected before selecting the integration:

| Library | Verified capability | Why not the initial backend |
| --- | --- | --- |
| [NNsight](https://nnsight.net/getting-started/quickstart/) | Explicit support for arbitrary PyTorch modules and tensor inputs; [MIT license](https://github.com/ndif-team/nnsight/blob/87f4dadaae254c6d36e8820cc83a251623b8dda7/LICENSE) | Its [persistent edits](https://github.com/ndif-team/nnsight/blob/87f4dadaae254c6d36e8820cc83a251623b8dda7/docs/usage/edit.md) run during later NNsight traces, requiring an inference-dispatch adaptation; it adds broader dependencies and [patches tensor backward](https://github.com/ndif-team/nnsight/blob/87f4dadaae254c6d36e8820cc83a251623b8dda7/src/nnsight/__init__.py#L178-L205) |
| [pyvene](https://github.com/stanfordnlp/pyvene/tree/9e333904dcf9e597ca76170010d17f4d4580de8d) | Generic interventions and built-in [activation addition](https://github.com/stanfordnlp/pyvene/blob/9e333904dcf9e597ca76170010d17f4d4580de8d/pyvene/models/interventions.py); [Apache 2.0 license](https://github.com/stanfordnlp/pyvene/blob/9e333904dcf9e597ca76170010d17f4d4580de8d/LICENSE) | Useful for richer trainable/composed interventions, but requires more model-adapter and dependency work for the first frozen MLP experiment |
| [steering-vectors](https://github.com/steering-vectors/steering-vectors/tree/5459bd1287be642ec75a4ab000dc833262bcb7f4) | CAA extraction and injection for language models; [MIT license](https://github.com/steering-vectors/steering-vectors/blob/5459bd1287be642ec75a4ab000dc833262bcb7f4/LICENSE) | [Training](https://github.com/steering-vectors/steering-vectors/blob/5459bd1287be642ec75a4ab000dc833262bcb7f4/steering_vectors/train_steering_vector.py) consumes text/tokenizers; [injection](https://github.com/steering-vectors/steering-vectors/blob/5459bd1287be642ec75a4ab000dc833262bcb7f4/steering_vectors/steering_vector.py#L91-L101) assumes token-shaped activations, so custom layer names alone do not make it an SB3 backend |

The pinned combination has now been exercised locally on Windows/Python 3.12 with both checkpoints and through the real SB3 prediction path. One integration issue required a small adapter: Baukit's optional-argument helper treats bound methods differently from plain functions, so the managed intervention passes a plain lambda that calls its editing method. This preserves reuse of Baukit's hook implementation. The integration tests cover batched shape handling, zero-strength identity, changed actions under an intervention, and hook removal on both success and exception.

PyTorch's own [forward-hook API](https://docs.pytorch.org/docs/stable/generated/torch.nn.Module.html#torch.nn.Module.register_forward_hook) is the minimal maintained fallback if the selected dependency later proves unsuitable. Avoid rebuilding a general intervention framework.

## Experiment infrastructure and reporting

- [uv projects](https://docs.astral.sh/uv/guides/projects/) supplies project initialization, local environments, dependency locking, and execution.
- [Python logging](https://docs.python.org/3.12/library/logging.html) supplies shared console/file handlers; logging format and research messages belong to this project.
- [NumPy compressed NPZ](https://numpy.org/doc/1.26/reference/generated/numpy.savez_compressed.html) supplies array artifacts.
- [NumPy array equality](https://numpy.org/doc/1.26/reference/generated/numpy.array_equal.html), [array byte serialization](https://numpy.org/doc/1.26/reference/generated/numpy.ndarray.tobytes.html), and [Python hashing](https://docs.python.org/3.12/library/hashlib.html) support the unchanged-vector import audit. A new evaluation label is a project hypothesis change; these APIs establish numerical identity, not semantic equivalence.
- [NumPy median](https://numpy.org/doc/1.26/reference/generated/numpy.median.html) supplies the reduction used by the fitting speed floor. The chosen fraction `0.5` is a project pilot heuristic supported by [experiment 001's fitting-only diagnosis](../reports/hc-classic-001-diagnostics.md), not a rule from NumPy or a steering paper.
- [Python ProcessPoolExecutor](https://docs.python.org/3.12/library/concurrent.futures.html#processpoolexecutor) supplies isolated rollout workers. The project uses spawned processes so workers do not share policy hooks or random-number-generator state.
- [Matplotlib plotting](https://matplotlib.org/stable/api/_as_gen/matplotlib.pyplot.plot.html) and [saved figures](https://matplotlib.org/stable/api/_as_gen/matplotlib.pyplot.savefig.html) supply strength-response charts.
- [ReportLab Platypus](https://docs.reportlab.com/reportlab/userguide/ch5_platypus/), [paragraphs](https://docs.reportlab.com/reportlab/userguide/ch6_paragraphs/), and [tables](https://docs.reportlab.com/reportlab/userguide/ch7_tables/) supply pagination and PDF layout. Reports read recorded results; the renderer performs no new selection or statistical tests.
- [pytest](https://docs.pytest.org/en/stable/) supplies tests for numerical contracts, simulator measurements, pairing, and cleanup.

The fixed-speed application uses [ImageIO streaming](https://imageio.readthedocs.io/en/stable/examples.html) and [Pillow frame annotations](https://pillow.readthedocs.io/en/stable/reference/ImageDraw.html) for paired videos. Its validation-derived target, 5% baseline-relative tolerance, 80% episode coverage, and zero-failure requirement are project application criteria, not recommendations from those media libraries. Video replay equality and fixed observation action checks support media correspondence and hook removal; they do not imply physical trajectory reversal.

The same media utilities now support signed lateral targets; the exact untested application specification is in [methodology](methodology.md#fixed-speed-application). Ant's published top-down and stationary-camera illustrations use [MuJoCo's public renderer](https://mujoco.readthedocs.io/en/3.1.5/python.html#rendering), [scene decoration](https://mujoco.readthedocs.io/en/3.1.5/APIreference/APIfunctions.html#mjv-connector), and Matplotlib for the measured XY plot. [Video reproduction](ant-videos.md) records the scene-only adaptations and publication sources; the [causal audit](../reports/ant-classic-005-causal-audit.md) checks the original simulator and actor against pinned upstream source.

The [documentation audit](../reports/documentation-audit.md) uses independent [NumPy means](https://numpy.org/doc/1.26/reference/generated/numpy.mean.html), [linear quantiles](https://numpy.org/doc/1.26/reference/generated/numpy.quantile.html), and paired-episode index resampling to check saved evidence without calling production extraction/statistics or simulation. It compares historical gates as metadata rather than selecting treatments again. The publication checker uses the [Hugging Face inventory API](https://huggingface.co/docs/huggingface_hub/package_reference/hf_api#huggingface_hub.HfApi.model_info), public HTTP reads and standard-library hashes. The [pytest import-path documentation](https://docs.pytest.org/en/stable/explanation/pythonpath.html) supplies the minimal test configuration fix for importing repository audit scripts through the documented `pytest` entry point.

## Related work reserved for later experiments

[Policy Gradient Steering](https://arxiv.org/abs/2607.27574v1) is a candidate escalation when natural contrast exists but classic vectors do not control the behavior. The published experiment pipeline does not integrate it; paused local prototype work is not a completed experiment. Continuous-action log probabilities and any trust-region/regularization machinery must be checked against the actual SAC/TQC distribution; categorical-language-model code is not directly interchangeable.

Command-conditioned HalfCheetah velocity is a possible online-RL training experiment, informed by [existing velocity-task wrappers](https://ut-austin-rpl.github.io/amago/_modules/amago/envs/builtin/half_cheetah_v4_vel.html). Training rewards, convergence criteria, and extraction pairs must be specified before that experiment and documented as adaptations.
